## 2. Как проверялось

- Статический разбор исходников (модули `math`, `body`, `fluids`, `material`).
- Сборка в песочнице (Rust 1.75). Эта версия не знает edition 2024, поэтому проверялась копия проекта с edition 2021 и без `rayon` и `env_logger`.
- Демо `main` запущено, записан вывод.
- Написаны тесты-пробы на подозрительные места (коллизии, AABB, гидростатика SPH).

**Ограничение:** сборку на вашей машине с edition 2024 независимо не подтверждал. Логические баги от тулчейна не зависят.

## 4. Архитектура и структура

- Подкаталог `body/types/*` (`static`, `kinematic`, `dynamic`, `mod`) пуст и **не подключён** в `body/mod.rs` — компилятор его не видит.
- `body/rigid/solver.rs` и `body/rigid/storage.rs` пусты.
- `Object` содержит `Option<ObjectPhysicProp>`: допустимы некорректные состояния (динамическое тело без параметров, статическое с параметрами).
- `ObjectId` без `Clone/Copy/Eq/Hash`, хранилища объектов нет.
- `world.rs` содержит только `WorldVertices` для `Polygon` и мир собой не представляет.
- Около 60 % кода — алгоритмы пар коллизий (10 файлов по 300–1148 строк), решателя нет.
- Собственный модуль `log` затеняет крейт `log`, поэтому в `main` приходится писать `::log`.
- Глобальные ре-экспорты в `lib.rs` (`pub use fluids::sph::*; material::*; world::*`) засоряют пространство имён.

## 5. Качество кода

### 5.1 `material/registry.rs`

- Два `.expect("REASON")` — плейсхолдер в рабочем коде; функция возвращает `Result`, но паникует и теряет путь к файлу.
- `read_dir` без сортировки: `MaterialId` зависят от файловой системы.
- Поиск по имени чувствителен к регистру (в `main` запрос `"Water"`, сообщение об ошибке говорит `water`).
- `warn!("No texture")` без имени материала срабатывает для 5 из 6 штатных материалов.
- `debug!("Texture loaded")` вводит в заблуждение: текстура не загружается.

### 5.2 `log.rs`

- `Assert => "assert"` не является уровнем логирования.
- `None => ""` вместо `"off"`.
- Ветка `_ => "another"` недостижима.
- Параметр `Level` нарушает `snake_case` и затеняет неиспользуемый импорт.
- `let _ = ….init()` бессмысленно; повторный вызов `init()` паникует.

### 5.3 `fluids/sph/config.rs`

- `SphConfig::default()` читает файл с диска и пишет в лог (побочные эффекты, зависимость от рабочего каталога).
- Отсутствие конфига пишется как `error!`, при этом работа продолжается.
- Значения `builtin()` продублированы в `config.ron`.

### 5.4 `main.rs`

- `debug!("Simulation finished")` не виден при уровне `Info`.
- Сообщение об ошибке расходится с запросом имени материала.

### 5.5 `Cargo.toml`

- `rayon` объявлен и не используется.
- `env_logger` — зависимость библиотеки, хотя нужна только бинарю.
- `panic = "abort"` в release у физической библиотеки.
- `strip = true` и `lto = "fat"` для библиотеки не имеют смысла.

**Наблюдения**

1. Первоначальные 9/10 у GPT и Gemini — оценка потенциала по структуре и объёму кода без запуска. После разбора оценки подправлены под критику, поэтому совпадение с цифрами Claude не вполне независимо.
2. Существенное расхождение — «скелет» (6–7 против 4): это спор об определении. Если скелет — раскладка модулей, 6–7 защитимо; если структура, способная нести нагрузку, — 4.
3. Расхождения 2 и 2–3, а также 4 и 3 — шум.
4. Все трое сходятся по тестам (1), ошибкам (3) и по фактам (давление SPH, `compute_aabb`, `MultiPoint`, `Default` с побочными эффектами).

## 9. Главные риски

1. **Нулевое давление в SPH.** Базовый режим не проходит простейший тест на гидростатику. Планируемые новые режимы жидкости нельзя будет ни отладить, ни сравнить.
2. **Отсутствие тестов.** Коллизии (~6000 строк) не проверены; четыре пробы нашли четыре дефекта.
3. **Незавершённая модель тел.** Пустые типы тел, решатель и хранилище делают невозможными контакты и интеграцию с жидкостью.
4. **Нет границ для жидкости.** Связь жидкость↔тела (пункт плана «система интеграций») не имеет под собой ничего.

## 10. Итог по версии 0.75.5 alfa

Версия соответствует ранней альфе: каркас модулей и объём геометрии есть, работоспособной физики нет. Для следующего отчёта ключевые контрольные точки: ненулевое давление в гидростатическом тесте, исправленные C1–C4, наличие тестов, подключённые типы тел.
